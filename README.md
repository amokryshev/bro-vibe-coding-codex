# Bro Vibe Coding

Bro Vibe Coding — плагин для Codex и Claude Code. Он объединяет bro, инженерные
навыки Matt Pocock и дополнительные инструменты: проверку безопасности, общие
инструкции, Jira/Atlassian, браузер Playwright и почту. При установке вы выбираете,
что использовать. Этот выпуск предназначен для **codex**, версия **0.1.0**.

**Чтобы начать:** выполните команду `npx` из папки проекта → выберите инструменты
в мастере → согласитесь на настройку проекта → после проверки откройте новую
сессию агента и вызовите bro.

## Перед установкой

Нужны macOS или Linux, Node.js 22+, npm/npx, Git, установленный и авторизованный
CLI выбранного агента с поддержкой плагинов, а также SSH-доступ к репозиторию
этого выпуска BRO. Проверьте `node --version`, `npm --version`, `git --version`
и `codex --version`. Windows пока не поддерживается.

Если установлен прежний комплект Setup/Main, сначала выполните его штатное
полное удаление по инструкции той версии. Сохраните соглашения проектов и
параметры аккаунтов перед переходом; автоматического переноса нет.

## 1. Запустить установку через npx

Откройте обычный интерактивный терминал и перейдите в существующий каталог
проекта, заменив путь ниже на свой. Затем выполните команду этого выпуска:

```sh
cd /absolute/path/to/project
npx @amokryshev/bro@0.1.0 --agent codex --release 0.1.0
```

`@0.1.0` закрепляет версию npm-launcher, `--release 0.1.0` выбирает
выпуск BRO. Это независимые версии. Launcher сам регистрирует marketplace,
устанавливает плагин штатной командой агента и запускает установленный мастер
в том же терминале. Перезапуск агента посередине не требуется.

Если npm доступен через локальный HTTP-прокси, включите его клиент и укажите
параметры перед именем пакета, заменив адрес на свой:

```sh
npx --https-proxy=http://127.0.0.1:1080 --proxy=http://127.0.0.1:1080 @amokryshev/bro@0.1.0 --agent codex --release 0.1.0
```

Копируйте команду одной строкой. Настройки npm-прокси не заменяют настройки
SSH-доступа к Git. При ошибке следуйте напечатанному следующему шагу и сохраните
путь к отчёту; выполненные этапы не откатываются автоматически. Повторная установка
поверх уже настроенного BRO отклоняется — используйте мастер для проверки состояния.

## 2. Выбрать инструменты и настроить компьютер

Отвечайте на вопросы мастера **в том же терминале**. Для работы с bro выберите
`bro-matt`. Стрелки перемещают курсор, пробел переключает инструмент, `A` выбирает
все, Enter продолжает, Ctrl+C отменяет. Пустой выбор допустим: управление через
`setup-bro` останется доступно; для изменения состава потребуется новая установка
после штатного удаления или сброса.

Мастер устанавливает выбранные инструменты и выполняет системную настройку.
Для Atlassian завершите предложенную OAuth-авторизацию. Для Playwright используется
браузер из выпуска либо явно выбранный вами исполняемый файл; получение и
распаковка браузера могут занять время.

`setup-matt-pocock-skills` — отдельный навык для соглашений о трекере и документации,
а не установщик BRO. Навыки Matt уже входят в `bro-matt`.


## 3. Настроить текущий проект и завершить установку

После системной настройки мастер спросит, настроить ли текущую папку как проект.
Проверьте показанный путь и выберите **«Да»**, чтобы сразу начать работу с bro.
Если выбрали «Нет», позже запустите `setup-bro` из нужного проекта и выберите
**«Настройка текущего проекта»**.

Для `bro-matt` настройка размещает bro и навыки Matt в `.agents/skills` у Codex
или `.claude/skills` у Claude. Если соглашения о трекере ещё нет, укажите,
например, `Jira BRO`, `GitHub owner/repository` или
`локальные Markdown-задачи в docs/tasks`. Доступ к внешнему сервису
настраивается отдельно. Если выбран Email, его lifecycle подготовит `.env`
проекта и предложит заполнить параметры по разделу ниже.

Существующие `AGENTS.md`, `CLAUDE.md` и `docs/agents` сохраняются. Дополнительные
параметры bro находятся в `.agents/bro-vibe-coding/project.md` или
`.claude/bro-vibe-coding/project.md`; общие инструкции проекта имеют приоритет.
Неизвестные установщику навыки и другие чужие файлы не заменяются автоматически.

При повторной настройке принадлежащие BRO проектные файлы переносятся
в `obsolette-backup/<дата-UUID>` внутри проекта. Общие файлы настроек сначала
копируются целиком, затем в них заменяются только записи BRO. Пользовательские
файлы внутри смешанных каталогов остаются на месте. Эти архивы сохраняются
и при удалении BRO.

Дождитесь сообщения launcher «BRO установлен и проверен». Проверку результата
он выполняет автоматически; повторно запускать установку через `setup-bro`
не нужно. После успешной проверки полностью завершите старую сессию
и запустите новую из настроенного проекта. Подтвердите требуемое агентом доверие
проекту, MCP и hooks; для Codex при необходимости проверьте hooks через `/hooks`.
Для каждого нового проекта повторяйте «Настройку текущего проекта».

## 4. Начать работу с bro

В чате Codex напишите:

```text
$bro Добавь поиск по списку заказов. Искать по номеру и имени клиента; пустой запрос показывает весь список. Сначала согласуем сценарии и дизайн.
```

В Claude Code:

```text
/bro Добавь поиск по списку заказов. Искать по номеру и имени клиента; пустой запрос показывает весь список. Сначала согласуем сценарии и дизайн.
```

Bro читает соглашения проекта, уточняет результат, выбирает подходящие навыки
и ведёт поручение до проверки. Перед реализацией программных изменений он
согласует сценарии и концептуальный дизайн. Отвечайте на вопросы, от которых
зависит результат, и проверяйте предложенные решения.

Другие варианты для Codex (в Claude замените `$bro` на `/bro`):

| Что нужно | Сообщение в чате |
| --- | --- |
| Выбрать работу | `$bro` — предложит доступные задачи из настроенного трекера |
| Взять существующую задачу | `$bro Возьми BRO-123. Прочитай описание и комментарии, проверь готовность к реализации.` |
| Продолжить работу | `$bro Продолжи BRO-123 с сохранённого плана и последнего результата проверки.` |
| Разобраться в коде | `$bro Объясни, как устроена авторизация в этом проекте, со ссылками на исходники.` |
| Найти причину сбоя | `$bro При сохранении заказа возникает ошибка. Вот шаги воспроизведения и лог: …` |

Можно вызывать отдельный навык: `$tdd`, `$code-review`, `$diagnosing-bugs`,
`$research`, `$to-spec`, `$to-tickets`, `$handoff`; в Claude — `/tdd`,
`/code-review` и так далее. Укажите конкретную задачу и ожидаемый результат.
Чтобы подробнее оформить соглашения о трекере и документации, вызовите
`$setup-matt-pocock-skills` (Claude: `/setup-matt-pocock-skills`). Это настройка
инженерных соглашений проекта, отдельная от установки плагина.

Если bro отсутствует в списке навыков, проверьте, что выбран `bro-matt`, выполнена
настройка именно этого проекта и новый процесс агента использует тот же профиль.

## Настройка и удаление после установки

Запускайте `setup-bro` из нужного проекта: `$setup-bro` в Codex или
`/bro-vibe-coding:setup-bro` в Claude. Действие выбирается в терминале мастера:

| Действие | Когда использовать |
| --- | --- |
| Установка на компьютер | Повторная настройка после сброса; при первом запуске npx мастер выполняет её автоматически |
| Настройка текущего проекта | Подключить новый проект или заново настроить существующий |
| Удаление из текущего проекта | Убрать ресурсы BRO только из этого проекта |
| Удаление с компьютера | Полностью удалить BRO либо сбросить его до начального состояния с доступным `setup-bro` |

Чтобы изменить состав инструментов или системные параметры, выберите удаление
с компьютера, затем выполните новую установку. Повторная установка поверх
существующей отклоняется. Настройка компьютера выполняется внутри установки.

При удалении из проекта мастер запрашивает подтверждение, затем удаляет
принадлежащие BRO навыки, настройки и рабочие данные этого проекта, включая
данные runtime Email. Пользовательский `.env`, общая установка, другие проекты, чужие файлы
и архивы `obsolette-backup` сохраняются. Чтобы вернуть проектные возможности,
снова выберите «Настройка текущего проекта».

Полное удаление требует подтверждения и удаляет ресурсы BRO **из всех настроенных
им проектов**, затем его общие настройки, авторизацию, кэши, файлы и регистрацию
плагина. Исходные пользовательские файлы аккаунтов и архивы сохраняются.
Второй режим — **«Сброс до начального состояния»**: после такой же очистки
мастер заново регистрирует маркетплейс и плагин из прежнего источника на том же
Git commit. После перезапуска агента доступен `setup-bro`; инструменты и проекты
нужно настроить заново. Сброс не обновляет выпуск и не восстанавливает прежние
параметры. Если маркетплейс используется другими плагинами, чужие ресурсы
сохраняются; сброс не меняет общий checkout и сообщает о конфликте.

После удаления вернитесь в чат: агент проверит результат напечатанной командой,
которая остаётся доступна даже после удаления плагина. Затем перезапустите агент.

При отмене до очистки изменения не выполняются. При прерывании или ошибке
системного удаления используйте напечатанную **Continue removal** команду:
исполнитель и журнал находятся вне удаляемого плагина. Если очистка не завершилась,
повторная регистрация не начинается; если не удалась регистрация, повтор продолжает
её без повторного удаления. Сохраните каталог журнала до завершения проверки.
Для других незавершённых действий снова вызовите `setup-bro`. Не удаляйте
каталог установки вручную: он содержит сведения о принадлежащих BRO ресурсах.

Для перехода на другой выпуск сначала выполните полное удаление, затем установите
новый выпуск командой `npx` из его README и пройдите мастер. Сохраните параметры для
повторной настройки. Отдельных действий `update`, `repair`, `migrate` и `recovery`
нет. Новая установка начинается с команды `npx` выше.
Если BRO установлен через прежний bootstrap, сначала удалите его штатными
lifecycle-командами той установки. В прежнем комплекте Setup/Main имя
`setup-bro` тоже использовалось, но его инструкции относятся к той версии.

## Какие инструменты выбирать

| ID в настройках | Возможность | Где настраивается |
| --- | --- | --- |
| `bro-matt` | bro и инженерные навыки Matt Pocock | В каждом проекте |
| `security-review` | Навык проверки безопасности и материалы OWASP | На компьютере |
| `session-start` | Общие инструкции при начале сессии | На компьютере |
| `subagent-start` | Инструкции для запускаемых подагентов | На компьютере |
| `permissions` | Правила разрешений для поддерживаемых интеграций | В каждом проекте |
| `managed-curl` | Управляемые GET-запросы без сохранения ответа в файл | В каждом проекте |
| `atlassian` | Подключение Jira/Atlassian через MCP и OAuth | На компьютере |
| `playwright` | Браузерные проверки через MCP | На компьютере |
| `email` | Работа с почтой через MCP | Аккаунт отдельно для каждого проекта |

Состав доступных инструментов определяется выпуском. Bro может работать
с локальными задачами без Atlassian. При выбранных общих инструкциях обычная
работа начинается с запуска агента; отдельной команды загрузки инструкций нет.

Примеры поручений для настроенных интеграций:

```text
Прочитай Jira-задачу BRO-123 и кратко изложи требования.
Через Playwright проверь оформление заказа на http://127.0.0.1:8000.
Через Playwright открой указанный сайт и найди условия доставки: …
Найди в настроенной почте письма по теме … за последнюю неделю.
```

В текущем плагине один Playwright-сервер обслуживает локальные и внешние сайты.
Для браузерной работы явно укажите, что требуется Playwright или проверка UI.
Для отправки почты отдельно укажите получателя и содержание сообщения.
Подключение инструмента не заменяет авторизацию и штатные разрешения агента.

Permissions добавляет 39 точных разрешений чтения/наблюдения Atlassian, Email и Playwright,
сохраняя шесть Jira write-исключений. Перечень хранится в `plugin/payload/permissions/policy.json`.
Запись Confluence, `download_attachment`, `extract_contacts`, `browser_tabs`,
`browser_navigate`, `browser_evaluate` и `browser_run_code` требуют подтверждения.
Codex получает точные `approve`/`prompt` с default `writes`, Claude — `allow`/`ask` и
Confluence ask-шаблоны. Новые методы Confluence требуют обновления точного каталога Codex;
defaults агентов не эквивалентны. Строгие пользовательские ограничения не ослабляются.
Чтение почты без вопроса допускает недоверенное содержимое в контекст; разрешённый
`browser_take_screenshot` сохраняет файл. Эти разрешения не заменяют поручение пользователя.

## Настройки без интерактивных вопросов

Для автоматизации используйте мастер из **установленного плагина** с явным
`--action`. Попросите агента определить абсолютный путь к его
`lifecycle/plugin/install.mjs`; путь зависит от профиля и кэша агента.
Например, для уже установленного BRO:

```sh
BRO_SETUP="/absolute/path/to/installed/plugin/lifecycle/plugin/install.mjs"
node "$BRO_SETUP" --action configure-project --project /absolute/path/to/project --tracker 'локальные Markdown-задачи в docs/tasks'
```

Первоначальная установка выполняется через `npx`, как описано выше.
Для удаления требуется `--yes`. Для `--action uninstall-system`
доступны `--removal-mode full` (по умолчанию) и `--removal-mode reset`.
`--action configure-system` больше не является действием мастера.
Без необходимых параметров инструменты могут задать вопросы в терминале.

Параметры других инструментов передаются через JSON-файл, например (email использует только окружение/`.env`):

```json
{
  "bro-matt": {"tracker": "Jira BRO"},
  "managed-curl": {"curl": "/usr/bin/curl"},
  "playwright": {"executable": "/absolute/path/to/browser"}
}
```

Оставьте нужные поля, замените примеры реальными значениями и добавьте
`--settings /absolute/private/bro-settings.json` к соответствующей команде.
`playwright.executable` нужен только для явно выбранного внешнего браузера.
Системная и проектная команды используют параметры своих областей настройки.
Список параметров мастера доступен через `node "$BRO_SETUP" --help`.

### Подключить Email

Выберите `email` при установке, затем в мастере выберите настройку текущего
проекта. Lifecycle самого email создаст `.env` в этом проекте или добавит
недостающие переменные, сохранив существующие значения и комментарии.
Новый файл создаётся с правами `600`. Заполните его локально и выберите
«Файл исправлен — проверить подключение». Например:

```dotenv
MCP_EMAIL_ADDRESS=user@your-domain.test
MCP_EMAIL_PASSWORD=your-application-password
MCP_EMAIL_IMAP_HOST=imap.your-domain.test
MCP_EMAIL_IMAP_PORT=993
MCP_EMAIL_IMAP_TLS=true
MCP_EMAIL_SMTP_HOST=smtp.your-domain.test
MCP_EMAIL_SMTP_PORT=465
MCP_EMAIL_SMTP_TLS=true
MCP_EMAIL_SMTP_STARTTLS=false
MCP_EMAIL_SMTP_VERIFY_SSL=true
```

Для SMTP 587 задайте `MCP_EMAIL_SMTP_PORT=587`, `MCP_EMAIL_SMTP_TLS=false`
и `MCP_EMAIL_SMTP_STARTTLS=true`. Скрипт проверит TLS и авторизацию IMAP/SMTP
без отправки письма. После успеха выберите «Завершить настройку» и перезапустите
агент. При ошибке исправьте `.env` и повторите проверку.

На каждом этапе доступно «Пропустить настройку», включая активную проверку.
Мастер продолжит остальные инструменты, а результат email будет `skipped`.
Существующая регистрация при пропуске сохраняется; изменения пользователя
в `.env` не откатываются. При удалении BRO `.env` также сохраняется.

Настройки берутся только из окружения процесса и `.env` целевого проекта.
Окружение имеет приоритет; пустое значение окружения не заменяется значением
из файла. При полном окружении заполнять шаблон не требуется, секреты в него
не копируются. Для работы только через окружение передайте его также host,
который запускает MCP. Следующий запуск email перечитывает `.env`.

В автоматизации без TTY неполные параметры или ошибка проверки завершают
действие с ошибкой. Для явного пропуска задайте `BRO_EMAIL_SETUP=skip` в
окружении установщика. Это управление настройкой, не почтовые реквизиты.

Внутренние серверы требуют явного разрешения в `BRO_EMAIL_PRIVATE_ENDPOINTS`,
например `mail.internal:993,mail.internal:465`; IPv6 — `[fd00::1]:993`.
Loopback и link-local адреса по-прежнему запрещены. Необязательные параметры:
`MCP_EMAIL_SMTP_POOL_ENABLED`, `MCP_EMAIL_SMTP_POOL_MAX_CONNECTIONS`,
`MCP_EMAIL_SMTP_POOL_MAX_MESSAGES`, `MCP_EMAIL_RATE_LIMIT`.

Прежний `email.accountFile` и JSON/TOML с аккаунтом больше не используются.
Повторно настройте email через окружение/`.env`: после успешного применения
новой регистрации удаляется только прежний принадлежащий BRO `account.json`.
Пользовательский исходный JSON не удаляется. Пароли вводите локально,
не в чат и не в аргументы команды; `.env` с секретами не включайте в Git.
