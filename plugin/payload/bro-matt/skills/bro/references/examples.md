# Примеры границ

## Быстрая проверка и полная ревизия

| Вход и состояние | Действие |
| --- | --- |
| Первый `$bro` в сессии, полный комплект без заглушек, даты не старше месяца | Быстро проверить документы и даты, сохранить успешный результат в диалоге; код не исследовать |
| Повторный `$bro` в том же проекте и сессии после успешной проверки | Использовать результат; повторно не читать документы, Git-историю или код |
| Новая сессия либо другой проект | Провести новую быструю проверку |
| На 30 октября документ обновлён 30 сентября | Дата допустима: ровно один календарный месяц |
| На 30 октября документ обновлён 29 сентября | Назвать файл и дату, предложить полную ревизию; без согласия её не начинать |
| На 31 марта невисокосного года документ обновлён 28 февраля | Дата допустима: в феврале нет 31-го, граница — последний день месяца |
| Пользователь не ответил на предложение ревизии или отказался | Продолжать независимое поручение; не считать даты свежими и не повторять предложение при каждом вызове |
| Нет ни одного документа обязательного комплекта, но есть код и project.md | Немедленно начать полную ревизию и подготовку контекста; разрешение на старт повторно не запрашивать |
| Есть соглашения, но отсутствуют словарь и обзор | Сообщить о частичном комплекте и предложить адресное восстановление; не запускать полную ревизию автоматически |
| Все файлы существуют, но содержат только заголовки и незаполненные поля | Сообщить о заглушках, предложить восстановление; физическое наличие файлов отличается от их полного отсутствия |
| Дата не установлена или находится в будущем | Сообщить о непроверенной дате; не выдавать успешную проверку и не менять дату ради неё |
| Пользователь явно просит полную ревизию, хотя проверка уже успешна | Выполнить полную ревизию по отдельной инструкции |

Проверяй явные альтернативные пути из соглашений проекта, не создавая дубли.
Устаревшая дата исторического ADR не делает текущий комплект просроченным.
Если несоответствие коду обнаружено позднее при выполнении поручения, сообщи о
конкретном противоречии; это не повод ретроспективно объявить быструю проверку
полной ревизией или автоматически перечитать весь проект.

## Полная ревизия через Matt Pack

В проекте есть код, но обязательных документов нет. Bro сразу начинает ревизию:
применяет `research` для обзора по исходникам, передаёт этот обзор в `grill-with-docs`
для выяснения целей и понятий; тот использует `grilling` и `domain-modeling`.
Затем `setup-matt-pocock-skills` оформляет недостающие соглашения. Bro принимает
результаты, проверяет комплект и возвращается к поручению. Интервью сохраняется
в диалоге, без создания Jira-задачи. При ревизии существующего контекста пригодные
соглашения сохраняются, а интервью пропускается, если не осталось неясных понятий
или решений. В итоговой записи названы применённые навыки и их результаты.

## Локальные задачи без внешних сервисов

Проект использует Markdown-задачи и `CONTEXT.md`. Пользователь вызывает bro с локальной задачей. Прочитай её, соглашения и актуальные решения; продолжай по сохранённому маршруту. Подключение внешнего трекера не является условием работы.

## Задача внешнего трекера при недоступной авторизации

Задание ссылается на недоступную задачу. Сообщи, какая операция вернула ошибку, и предложи конкретный штатный способ входа доступного host. Чтение разрешённого локального кода может продолжаться; содержание задачи не выдумывай. Независимую работу и блокируемый шаг различай. После входа подтверди доступ чтением нужной задачи.

## Готовая задача

Сценарии, дизайн, точная редакция и ответ пользователя уже сохранены. Прочитай их, сверь с текущими требованиями и продолжи следующий шаг. Повторное согласование тех же материалов не нужно.

## Багфикс

Пользователь просит устранить повторное создание заказа. До реализации исследуй путь запроса, опиши текущее и требуемое поведение при повторе, отказе и конкуренции, предложи минимальный дизайн и проверки. Согласуй эти конкретные результаты и сохрани ответ. Само наличие слова «исправь» не подтверждает ещё не показанный дизайн.

## Вопрос без разработки

Пользователь просит сравнить два способа отправки уведомлений без изменения кода. Исследуй варианты и дай сравнение в согласованных границах. Задача на реализацию и классы будущей системы не нужны.

## Спонтанное поручение без Jira

Пользователь просит небольшую правку, прототип или разбор «что если», не запрашивая задачу Jira. Выполни поручение; интервью и решения при необходимости сохраняй в диалоге. Предложение записать выполненную работу в Jira появляется только в итоговом ответе. Сама запись требует последующего согласия.

## Явное создание или существующая задача

«Создай задачу Jira на этот прототип» разрешает создать задачу сразу после проверки дублей. «Исправь BRO-123» означает работу в существующей задаче; новую задачу и предложение повторно зафиксировать эту работу не добавляй.

## Завершающий проход по стилю

После изменения Python-кода просмотри затронутый код на единообразие имён, отступов, импортов и оформления, используя собственные знания и уже известные соглашения. Исправь стиль без изменения поведения и повтори затронутые проверки. Дополнительные руководства и интернет для этого прохода не нужны; остальной репозиторий не переформатируй. После исследования без правок кода стилевого прохода нет.

## Частичное поручение

Общая задача включает три сценария, пользователь поручил только исследовать один. Сохрани выводы и проверки этого исследования; не закрывай всю задачу и не начинай остальные сценарии без соответствующего поручения.

## Независимая проверка недоступна

Host не предоставляет отдельный контекст, а критерии требуют независимого review. Выполни доступные собственные проверки, сохрани их результаты и явно оставь независимое review невыполненным. Не называй собственный повторный просмотр независимым.
