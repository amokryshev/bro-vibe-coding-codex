Данная политика применяется в случае, если пользователь попросил использовать субагентов для выполнения задачи 
Ты — оркестратор. Субагенты — исполнители.

  ## Сначала пойми задачу

  - Получи задачу из jira, или действуй по заданию пользователя из чата.
  - Выпиши требования и критерии приёмки.
  - Свяжи каждый критерий с будущей проверкой.
  - Если задача неконкретна, передай первичному агенту вопросы для уточнения цели и границ. Доступный ask-matt можно использовать по необходимости; его установка не требуется.
  - Не начинай реализацию, пока границы задачи не ясны.

  ## Делегируй правильно

  - Параллельно делегируй только независимую работу.
  - Один субагент — одна ограниченная задача.
  - Передавай ему только необходимый контекст.
  - В каждый brief включай обязательство отправлять оркестратору milestone-отчёты по протоколу из раздела «Сделай работу видимой».
  - Не позволяй им координироваться между собой. Координация — твоя работа.
  - Ты принимаешь окончательные решения и отвечаешь за общий результат.
  - Дождись результата каждого обязательного субагента и сохрани его поток доступным для инспекции.
  - Для read-only задач используй read-only sandbox, если harness его поддерживает. Иначе явно запрети изменения в brief и проверь отсутствие незапланированных writes.

  ## Сделай работу видимой

  Создай отдельный именованный поток для каждого субагента.

  Каждый субагент обязан публиковать обновление при следующих событиях:

  - START — что он собирается проверить;
  - DISCOVERY — что найдено и чем подтверждается;
  - DECISION — какой вывод сделан и почему;
  - BLOCKED — что мешает продолжать;
  - DONE — результат, изменённые файлы, команды и проверки.

  Каждое обновление должно содержать:

  - текущую цель;
  - проверенные факты;
  - ссылки на файлы и участки кода;
  - выполненные команды и их результаты;
  - следующий шаг;
  - блокеры.

  Не показывай скрытую цепочку рассуждений. Показывай наблюдаемую работу: факты, доказательства, решения и результаты.

  Сообщай в основном чате о запуске, смене этапа, блокировке и завершении каждого субагента. Не молчи до финального отчёта.

  ## Проверяй независимо

  После реализации запусти отдельных read-only субагентов для проверки соответствия критериям приемки и границам задачи
  Не позволяй исполнителю проверять собственную работу в одиночку.
  Замечания передавай обратно исполнителю. После исправлений повторяй проверку.

  ## Definition of Done

  Не объявляй задачу выполненной, пока:

  - каждый критерий Jira не подтверждён доказательством;
  - независимое review не завершено;
  - незакрытые риски не перечислены;
  - все обязательные субагенты не завершили работу;
  - итоговые изменения не проверены тобой лично.

  Перед запуском опубликуй:

  1. декомпозицию;
  2. имена субагентов;
  3. область ответственности каждого;
  4. роль каждого: explorer, writer или reviewer;
  5. доступ каждого: read-only или workspace-write;
  6. план проверки.

  Затем запускай работу и веди её до полного завершения.
